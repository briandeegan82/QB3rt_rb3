Lab: Talk to a Robot — ROS 2 Talker / Listener over Wi‑Fi

In this lab you will connect your laptop to a Qualcomm RB3 Gen 2 robot over Wi‑Fi and exchange ROS 2 messages between the two computers. You will run a talker on the robot and watch its messages arrive at a listener on your laptop — your first distributed ROS 2 system. Works on Linux, macOS, and Windows.

What you'll learn

  • Connect to a networked robot over SSH.
  • How ROS 2 finds other nodes: the domain ID, the RMW, and unicast discovery.
  • Run and observe a talker/listener spanning two machines.

Before you start

  • Your laptop has pixi with a RoboStack ROS 2 Jazzy environment (Linux, macOS, or Windows).
  • From your instructor you have two numbers for your robot: its ROS domain and its IP address, plus the ubuntu SSH password.
    These are not the same — e.g. robot #1 uses domain 1 but IP 192.168.0.201.
⚠ Connect to the lab Wi‑Fi ONLY. Unplug wired Ethernet and turn off any VPN before you start. If your laptop is on more than one network, ROS 2 usually tries to talk over the wrong one and the listener stays silent — this is the #1 reason this lab "doesn't work."
Key idea. The lab Wi‑Fi has multicast turned off, so ROS 2's automatic discovery can't find the robot. We use CycloneDDS with an explicit unicast peer (the robot's IP), and both computers must use the same ROS_DOMAIN_ID (the robot's domain, not its IP).

Step 1 — Connect to the robot and start the talker

Open a terminal (macOS/Linux: Terminal; Windows: Windows Terminal or PowerShell — both include ssh). Use your robot's IP:

ssh ubuntu@192.168.0.201        # <-- your robot's IP; enter the ubuntu password

The robot sets up ROS 2 automatically at login. Confirm its domain, then start the talker:

cat /etc/qb3rt/domain_id            # <-- this is the robot's DOMAIN (e.g. 1) — note it!
ros2 run demo_nodes_cpp talker

You should see it publishing once per second. Leave it running and switch to a second terminal on your laptop.

[INFO] [talker]: Publishing: 'Hello World: 1'
[INFO] [talker]: Publishing: 'Hello World: 2'
...

Step 2 — On your laptop: activate ROS 2 (all OSes)

In your RoboStack pixi project, add the two packages this lab needs (first time only), then enter the environment:

cd ~/robostack/ros2-jazzy-ws          # your pixi project (path will vary)
pixi add ros-jazzy-demo-nodes-cpp ros-jazzy-rmw-cyclonedds-cpp   # once
pixi shell

Step 3 — On your laptop: point ROS 2 at your robot

You set three things: the domain (match the robot), the RMW (CycloneDDS), and a small config file that lists your robot's IP as a unicast peer. Commands differ by OS — pick yours.

macOS / Linux (bash or zsh):

export ROS_DOMAIN_ID=1                          # your robot's DOMAIN (e.g. 1)
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp

cat > ~/rb3_dds.xml <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<CycloneDDS xmlns="https://cdds.io/config">
  <Domain Id="any">
    <General><AllowMulticast>false</AllowMulticast></General>
    <Discovery>
      <ParticipantIndex>auto</ParticipantIndex>
      <MaxAutoParticipantIndex>120</MaxAutoParticipantIndex>
      <Peers>
        <Peer address="localhost"/>
        <Peer address="192.168.0.201"/>      <!-- YOUR robot's IP -->
      </Peers>
    </Discovery>
  </Domain>
</CycloneDDS>
EOF

export CYCLONEDDS_URI=file://$HOME/rb3_dds.xml

Windows (PowerShell — this is what pixi shell opens on Windows):

$env:ROS_DOMAIN_ID = "1"                          # your robot's DOMAIN
$env:RMW_IMPLEMENTATION = "rmw_cyclonedds_cpp"

@'
<?xml version="1.0" encoding="UTF-8"?>
<CycloneDDS xmlns="https://cdds.io/config">
  <Domain Id="any">
    <General><AllowMulticast>false</AllowMulticast></General>
    <Discovery>
      <ParticipantIndex>auto</ParticipantIndex>
      <MaxAutoParticipantIndex>120</MaxAutoParticipantIndex>
      <Peers>
        <Peer address="localhost"/>
        <Peer address="192.168.0.201"/>
      </Peers>
    </Discovery>
  </Domain>
</CycloneDDS>
'@ | Set-Content -Encoding ascii $env:USERPROFILE\rb3_dds.xml

$env:CYCLONEDDS_URI = "file:///" + ($env:USERPROFILE -replace '\\','/') + "/rb3_dds.xml"

Edit the 192.168.0.201 line to your robot's IP before running the block. (On Windows you can also just open Notepad, paste the XML, and Save As rb3_dds.xml in your user folder.)

Step 4 — Run the listener

ros2 run demo_nodes_cpp listener

Within a couple of seconds you should see the robot's messages arriving on your laptop:

[INFO] [listener]: I heard: [Hello World: 42]
[INFO] [listener]: I heard: [Hello World: 43]
...
🎉 That message travelled from the robot, across the Wi‑Fi, to your laptop. The numbers continue from wherever the talker currently is — that's expected.

Step 5 — Inspect the system (optional)

Open another laptop terminal, pixi shell, and re‑run the domain / RMW / CYCLONEDDS_URI lines from Step 3. Then:

ros2 topic list        # includes /chatter
ros2 node list         # /talker (robot) + /listener
ros2 topic echo /chatter

Step 6 — Reverse the roles (optional)

  • Robot terminal: Ctrl + C, then ros2 run demo_nodes_cpp listener.
  • Laptop terminal: Ctrl + C, then ros2 run demo_nodes_cpp talker.

Now your laptop talks and the robot's terminal prints I heard: ….

Troubleshooting

Symptom Fix
Listener prints nothing Work through, in order: (1) Unplug Ethernet / turn off VPN — be on lab Wi‑Fi only. (2) ROS_DOMAIN_ID must equal the robot's domain (from cat /etc/qb3rt/domain_id), not its IP. (3) The <Peer> IP in rb3_dds.xml must be the robot's IP. (4) CYCLONEDDS_URI is actually set (print it). (5) You can reach the robot: ping 192.168.0.201.
Still nothing, and you must keep Ethernet/VPN on Force CycloneDDS onto your Wi‑Fi by your laptop's own lab IP. Find it — macOS: ipconfig getifaddr en0; Linux: hostname -I; Windows: ipconfig (the 192.168.0.x address). Then add inside <General> in rb3_dds.xml:
<Interfaces><NetworkInterface address="192.168.0.YOURLAPTOP"/></Interfaces>
ros2: command not found You didn't enter the environment — run pixi shell in your ROS pixi project first.
Package 'demo_nodes_cpp' not found Laptop: pixi add ros-jazzy-demo-nodes-cpp. Robot: tell your instructor.
ssh: command not found (Windows) Use Windows Terminal/PowerShell (has ssh). If missing: Settings → Apps → Optional Features → add "OpenSSH Client", or use PuTTY.
Can't SSH / Permission denied Check the robot IP and password; test ping 192.168.0.201 first.

Cleanup

  • Ctrl + C in each terminal to stop the nodes.
  • In the robot terminal, type exit to close the SSH session.
For instructors. Give each student their robot's domain and IP separately (they're decoupled: e.g. domain 1 → IP .201, because .1 is the AP gateway). Robots run CycloneDDS unicast (multicast off) on ROS_DOMAIN_ID = domain; ensure ros-jazzy-demo-nodes-cpp is installed on each and distribute the ubuntu password. The dominant support issue is multi‑homed laptops (corporate Ethernet / VPN) — pushing "lab Wi‑Fi only" up front avoids most of it.
